# Яндекс.Метрика 108408263: настройка и проверка

## Безопасное включение

Production-сборка задаёт `VITE_YANDEX_METRIKA_ENABLED=true` после локальной приёмки. Для проверки
соберите отдельный локальный preview с `VITE_YANDEX_METRIKA_ENABLED=true`. Не меняйте
`VITE_FORM_DELIVERY_ENABLED=false` и не задавайте публичный endpoint формы до отдельного
приёмочного теста доставки.

Счётчик загружается только после явного выбора «Принять» в cookie-баннере. Выбор хранится
в `localStorage` под ключом `alab_cookie_consent` не более 365 дней. «Отклонить» не загружает
скрипт. Ссылка «Настройки cookie» удаляет выбор и доступные cookies/storage Метрики,
вызывает `ym(108408263, 'destruct')` и перезагружает страницу для нового выбора.

## Цели в кабинете Метрики

В счётчике `108408263` создайте три цели типа «JavaScript-событие». Идентификаторы должны
в точности совпадать с кодом:

- `form_success` — только ответ сервера `ok: true` и `accepted: true`;
- `telegram_click` — ссылки на Telegram;
- `external_click` — остальные внешние HTTP(S)-ссылки.

Код вызывает только `ym(108408263, 'reachGoal', goalId)` и не передаёт параметры, значения
полей или текст ссылок. Telegram классифицируется раньше прочих внешних ссылок, поэтому одно
нажатие не создаёт одновременно `telegram_click` и `external_click`.

Для `tel:`, `mailto:`, мессенджеров и отправки формы ручные дубли автоматических целей
не создаются. Исключения — явно запрошенные `telegram_click` и `form_success`: первая нужна
как отдельная бизнес-цель Telegram, вторая фиксирует только подтверждённую сервером заявку,
а не любую попытку отправки формы.

## Настройки приватности в кабинете

1. Включите Вебвизор только после проверки разметки защиты полей.
2. На вкладке Вебвизора отключите «Записывать все поля».
3. Убедитесь, что в интерфейсе не настроено разрешение записи чувствительных полей.
4. Не используйте класс `ym-record-keys`.

Все поля контактной формы имеют `ym-disable-keys`, а вся форма дополнительно закрыта
`ym-hide-content`. Инициализация использует `sendTitle: false`. Автоматический PageView
отключён через `defer: true`; код отправляет один ручной `hit` по origin + pathname без
query/hash, с таким же очищенным referrer. Автоматическое отслеживание ссылок выключено,
чтобы адреса ссылок не попадали в дополнительные события помимо обезличенных целей.
Существующая first-party аналитика также удаляет query/hash и текст/адрес внешней ссылки;
на production GitHub Pages её endpoint отсутствует, поэтому она там ничего не отправляет.

## Проверка через `_ym_debug=2`

1. Запустите тестовую сборку с включённой Метрикой и откройте
   `http://localhost:<порт>/?_ym_debug=2` в новом профиле или после очистки данных сайта.
2. До выбора в баннере откройте DevTools → Network. Запросов к `mc.yandex.ru`,
   `mc.yandex.com` и `yandex.ru` от Метрики быть не должно; `window.ym` не должен быть
   создан кодом сайта.
3. Нажмите «Отклонить», обновите страницу и повторите проверку: запросов Метрики нет.
4. Через «Настройки cookie» сбросьте выбор, нажмите «Принять». Должен загрузиться один
   `tag.js?id=108408263`, а во вкладке Counters отладчика появиться только счётчик
   `108408263`. Во вкладке Console должен быть один PageView с URL без query/hash и без title.
5. Включите Preserve log и по одному проверьте Telegram и обычную внешнюю ссылку.
   На вкладках Events/Console ожидаются соответственно `telegram_click` и `external_click`.
   Для Telegram не должно быть второго события `external_click`. Телефон, email и форма
   должны учитываться существующими автоматическими целями без ручных `phone_click` и
   `email_click`.
6. При `VITE_FORM_DELIVERY_ENABLED=false` валидная попытка отправки должна завершаться
   сообщением о недоступности, без `form_success`. Для окончательной проверки этой цели
   нужен отдельный стенд с реальным endpoint: цель должна появиться только после ответа
   `ok: true, accepted: true`, но не при валидации, network error, HTTP error или malformed
   response.
7. Нажмите «Настройки cookie» после запуска Метрики. До перезагрузки должен выполниться
   `destruct`, после неё снова должен появиться баннер; новые запросы и цели не отправляются
   до повторного согласия.
8. Повторите сценарий с блокировщиком рекламы. Страница и ссылки должны работать без ошибок;
   отсутствие целей при заблокированной Метрике ожидаемо.

Для закрытия отладчика используйте `?_ym_debug=0`. Отладочный параметр следует применять
только на тестовом включении; ручная приёмка выполнена перед включением production-флага.
