# Передача сайта alabspace.com

Сайт передан студии A.LAB целиком. Дальнейшая разработка и поддержка — на стороне студии.
Этот файл — всё, что нужно знать, чтобы ни о чём не спрашивать прежнего разработчика.

## Репозиторий

Репозиторий передан на аккаунт студии через GitHub «Transfer ownership». Все соавторы,
issues, pull requests, настройки Actions и Pages переезжают вместе с ним. Старый адрес
`DenisDaraganGarden/alab-portfolio` редиректит на новый.

После принятия передачи один раз проверить: **Settings → Pages** — в поле Custom domain
должно стоять `alabspace.com`, галочка Enforce HTTPS включена. Если поле пустое — вписать
домен и сохранить, сертификат выпустится в течение часа.

Как запускать редактор и публиковать — [README](../README.md). Как пользоваться
редактором — [customer-guide.html](customer-guide.html).

## Хостинг и деплой

GitHub Pages. Пуш в `main` → GitHub Actions собирает сайт → выкладка за 1–2 минуты.
Vercel не используется; `vercel.json` и `.vercelignore` — остатки старой попытки, можно удалить.

**Ветку `main` защищать нельзя**: кнопка «Опубликовать» в редакторе пушит в неё напрямую,
обязательный Pull Request её сломает.

## Черновик «ГРАНИ»

Единственный неопубликованный кейс: `docs/drafts/grani.json`, картинки уже лежат в
`public/images/GRANI/`. Импорт: редактор → вкладка «Проекты» → «Импорт» → выбрать файл.

## Домены

`alabspace.com` (сайт) и `alabspace.ru` (почта work@alabspace.ru на Яндексе) зарегистрированы
на REG.RU на аккаунт студии, DNS управляется там же — прежний разработчик к доменам отношения
не имеет. Оплачены: `.com` до 05.02.2028, `.ru` до 05.02.2027.

DNS сейчас: апекс → A-записи GitHub Pages (185.199.108–111.153), `www` → CNAME на
`denisdaragangarden.github.io`. После передачи репозитория сайт продолжает работать без
изменений в DNS; при желании `www` можно перевести на `kildishewa.github.io`.
DNS-записи для подрядчика (подтверждения, DKIM для писем) студия вносит сама в кабинете REG.RU.

## Сервисы Яндекса и Google

Всё заводится студией на свои аккаунты, от прежнего разработчика ничего не требуется:

- **Яндекс.Вебмастер** — добавить `https://alabspace.com`, подтвердить своим мета-тегом
  `yandex-verification` в `<head>` `index.html`. Старый тег после этого можно удалить.
- **Google Search Console** — ресурс «Префикс URL» `https://alabspace.com/`, подтверждение
  «Тег HTML» в `<head>` `index.html`. Старое подтверждение уже снято.
- **Яндекс.Метрика** — счётчик `108408263` в `index.html` работает, но принадлежит аккаунту
  прежнего разработчика. Два варианта: заменить на свой счётчик в `index.html` (история
  с апреля 2026 останется недоступной) или прислать Яндекс ID студии — счётчик переносится
  вместе с историей одним действием.
- **Yandex Cloud** для обработчика формы — на Яндекс ID студии; подрядчику роль `admin`
  на отдельный каталог. Форма укладывается в бесплатный лимит Cloud Functions.

## Что не работает и требует доработки

- Форма обратной связи на сайте заявки никуда не отправляет — обработчик в
  `js/sections/contacts.js` только показывает «ОТПРАВЛЕНО». Нужен серверный обработчик.
- Собственный сбор статистики в редакторе на боевом сайте не работает: фронтенд шлёт события
  в `/api/analytics/collect`, а GitHub Pages — статика. Рабочая аналитика — только Метрика.

## Секреты

В GitHub нет ни секретов, ни переменных — сборка их не требует. Локальный `.env` нужен только
редактору, каждый создаёт свой по `.env.example` (со значениями из примера редактор
намеренно не стартует).
